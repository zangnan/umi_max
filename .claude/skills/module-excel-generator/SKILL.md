# 模块 Excel 配置生成器

AI 驱动的交互式设计助手。用户只需描述业务需求（如"企业员工管理"），Skill 自动推导并生成完整的模块配置 Excel 文件。

**关键原则**：
- 调用脚本**之前**，必须完成所有数据结构设计和关联关系确认
- 脚本是纯执行工具，**不接受任何 AI 推理或查询**
- 用户确认环节必须展示完整的表、主键、关联关系信息

## 执行流程（强制顺序）

```
Step 1: 表设计 → 输出完整表结构
Step 2: 模块设计 → 输出模块配置
Step 3: 字段设计 → 输出字段配置
Step 4: 菜单设计 → 输出菜单配置
Step 5: 自行检查校验 → 如检查不符合规则，则自动修正设计（与AI自身交互），交互后重复执行 Step 5 直至成功
Step 6: 用户确认 → ⚠️ 必须等待用户确认后才能调用脚本
Step 7: 调用脚本 → 生成 Excel
```

**⚠️ 绝对禁止**：在用户确认之前调用脚本生成 Excel

**Step 5 校验内容（确认前检查清单）**：
- [ ] rel2 中间表主键必须是 `uuid`（不带表名前缀）
- [ ] rel2 中间表必须包含 3 个字段：`uuid`、主表主键外键、关联表主键外键
- [ ] rel 关联字段命名与关联表主键一致
- [ ] 子表外键命名与主表主键一致

**校验失败时**：自动修正设计错误，修正后重新校验，直至成功

**跳过用户确认的后果**：
- 视为违反 Skill 规范
- 生成的文件可能不符合用户需求
- 浪费时间返工

## 工作流程

### Step 1: 表设计

**收集信息**:
- 表中文名 + 表英文名（格式: `中文名 表英文名`）
- 字段列表（字段名、中文名、数据类型、键、默认值、非空、备注）
- 关联配置（如需关联表展示：`rel` 或 `rel2` 属性）

**字段 JSON 结构示例**:
```json
{
  "name": "tag_id",
  "name_cn": "标签",
  "type": "varchar(32)",
  "rel": "rel:eg_m_tag&tag_name"
}
```

**字段验证规则**:
- 字段名: `^[a-z][a-z0-9_]*$`（小写英文+数字+下划线）
- 字段中文名: **必填**，不能为空
- 数据类型: `varchar(n)`, `char(n)`, `decimal(m,n)`, `int(n)`, `datetime`, `long`
- rel/rel2: 关联表展示时填写，格式为 `rel:{模块key}&{显示字段}` 或 `rel2:{模块key}&{显示字段}&{关联表模块key}`

### Step 2: 模块设计

**31 列配置**，关键项：

| 配置项 | 可选值 | 说明 |
|--------|--------|------|
| 列表边框 | `1` | |
| 列表首选项 | `checkbox`/`radio`/空 | |
| 工具栏按钮 | `1`/空 | 增加/删除/编辑/导入/导出/设置/全屏/刷新/筛选 |
| 工具栏导出 | `1`/`1,pdf`/`2` | `1`前端导出，`2`后端导出 |
| 表单布局 | `horizontal`/`vertical`/`4` | 水平/垂直/四列 |
| 表单宽度 | `960`/`1200`/`max` | |
| 自定义按钮 | `按钮名&方法名&参数` | 多值逗号分隔 |

### Step 3: 字段设计

**37 列配置**，按字段循环。

**Sheet 结构**:
- 每组第一行: `模块名称 模块key`（如 `企业员工管理 eg_m_hr_employee`）

| 外键字段 | 空 | 以 `_uuid` 结尾 | `1` |

**关键配置**:

| 类别 | 配置项 | 可选值 |
|------|--------|--------|
| 列表 | 列宽、对齐、固定、隐藏、排序、统计 | `120`, `L`, `1` |
| 筛选 | 类型、位置、占位符 | 类型: `Input`, `Select`, `DatePicker`; 位置: 空/`工具栏`/`列表头` |
| 表单 | 类型、格式化、只读、验证 | `必录`, `电话`, `邮箱` |

**格式化类型**:
- 日期: `YYYY-MM-DD`
- 数值: `0,0.00`
- 开关: `switch:0,1`
- 树结构: `tree:key`
- 码表: `code_dm_xxx`

**字段初始排序**: `asc,10` / `desc,20`（升序/降序 + 优先级）

## 表结构规范（必须遵守）

### 1. 子表外键命名规则

**规则**：子表外键**必须采用主表主键的完整名称**

```
主表主键: person_uuid
子表外键: person_uuid  ✓（完全一致）
子表外键: person_id     ✗（错误）
```

### 2. rel（一对多）关联字段命名规则

**规则**：主表中存储关联表的字段名**必须与关联表的主键名完全一致**

```
关联表 (tag) 主键: tag_uuid
主表 (person) 关联字段: tag_uuid  ✓（完全一致）
主表 (person) 关联字段: tag_ids   ✗（错误）
```

**字段长度规则**：rel 关联字段长度应设置为 `varchar(2000)`，因为需要存储多个关联表主键（逗号分隔）

```
存储格式: "tag1_uuid,tag2_uuid,tag3_uuid"
```

### 3. rel2（多对多）中间表结构规则

**规则**：中间表**必须包含三部分**：
1. 中间表自有主键
2. 指向主表的外键（与主表主键名一致）
3. 指向关联表的外键（与关联表主键名一致）

```
主表: person (主键: person_uuid)
关联表: permission (主键: permission_uuid)
中间表: person_permission
├── person_permission_uuid (PK)  ← 中间表自有主键
├── person_uuid (FK) ◄─────────────── 与主表主键一致
├── permission_uuid (FK) ◄─────────── 与关联表主键一致
```

## 输出文件

- **命名**: `{模块名称}_{模块key}_{timestamp}.xlsx`
- **目录**: `./exports/module_configs/`
- **格式**: 与模板一致（字体、背景色、边框、列宽）

**多模块合并规则**：
- 除非用户明确说明要分成多个文件，否则多个模块应生成到**一个 Excel 文件**
- 使用 `--groups` 参数指定主子表和关联表关系：

```
主表|sub:子表1,子表2|rel:关联表1|rel2:关联表2
```

| 前缀 | 含义 | 处理方式 |
|------|------|---------|
| `sub:` | 子表（Master-Detail） | 创建 leaf: 分隔行 + 外键字段 |
| `rel:` | 一对多关联表 | 创建 rel: 格式化字段 |
| `rel2:` | 多对多关联表 | 创建 rel2: 格式化字段；如指定中间表：`rel2:关联表,中间表` |

**rel2 中间表说明**：
- `rel2:标签管理`：自动查找包含主表外键和标签管理主键外键的表作为中间表
- `rel2:标签管理,发票与标签关系表`：显式指定 `发票与标签关系表` 作为中间表，中间表不生成独立菜单

**四种使用场景示例**：

| 场景 | groups 参数 |
|------|-------------|
| 主表 + 2张子表 | `人员管理\|sub:人员学历管理,人员工作经历管理` |
| 主表 + 2张关联表 | `人员管理\|rel:性格标签管理\|rel2:权限管理` |
| 主表 + 2子表 + 2关联表 | `人员管理\|sub:人员学历管理,人员工作经历管理\|rel:性格标签管理\|rel2:权限管理` |
| 多主表 | `人员管理\|sub:子表;部门管理\|sub:部门类别;职位管理\|rel:职位表` |

**注意**：
- `rel2:` 后可跟关联表名（自动查找中间表）或 `关联表名,中间表名`（显式指定中间表）
- 中间表不生成独立菜单，仅供 rel2 关联使用

## 主子表模块（Master-Detail）

主子表是一种"数据列表+数据采集"的扩展模式，用于维护一对多关系的数据。

### 场景示例

- 员工（主表）+ 学历（子表）+ 工作经验（子表）
- 发票头（主表）+ 发票明细（子表）
- 报关单头（主表）+ 报关单明细（子表）

### 分隔行（leaf）规则

主子表通过字段 Sheet 中的分隔行（leaf）实现关联。分隔行是列表中的虚拟列，点击后展开子表数据。

**分隔行字段配置（37列）**：

| 列索引 | 列名 | 值 | 说明 |
|--------|------|-----|------|
| 1 | 数据字典 | **空** | 分隔行特征：此项为空 |
| 2 | 字段名称 | **空** | 分隔行特征：此项为空 |
| 3 | 字段中文名 | `教育经历` | 显示文本 |
| 13 | 列表项格式化 | `leaf:eg_m_staff_education&staff_name` | 格式：`leaf:<子模块key>&<关联显示字段>` |
| 25 | 表单项开启 | **空** | 分隔行不是数据字段 |
| 26 | 表单类型 | **空** | 分隔行不是数据字段 |
| 27 | 表单格式化 | **空** | 分隔行不是数据字段 |

**leaf 格式说明**：
- 语法：`leaf:<子模块key>&<关联显示字段>`
- 示例：`leaf:eg_m_staff_education&staff_name`
- 表示：点击此分隔行，展示 `eg_m_staff_education` 子模块，标题使用 `staff_name` 字段

**分隔行文本推断规则**：
| 表名特征 | 推断文本 |
|----------|----------|
| 以"教育"、"学历"、"学习"结尾 | `教育经历` |
| 以"工作"、"履历"、"经历"结尾 | `工作经历` |
| 以"荣誉"、"奖励"、"称号"结尾 | `荣誉` |
| 以"明细"、"详情"结尾 | `明细` |
| 其他 | 表中文名最后4字 |

### Sheet 写入规则

| Sheet | 是否包含分隔行 | 说明 |
|-------|---------------|------|
| 表 | **否** | 分隔行是字段 Sheet 的虚拟列，不写入表 Sheet |
| 模块 | - | 每组表对应一个模块 |
| 字段 | 是 | 分隔行写入字段 Sheet |
| 菜单 | - | 只需为主表创建菜单 |

### 主子表字段 Sheet 结构

```
行1: 表头 (37列)
行2: 模块首行: 企业员工 eg_m_staff
行3: staff_uuid, 员工UUID, ...
行4: staff_code, 员工编号, ...
行5: staff_name, 员工姓名, ...
...
行8: (空), (空), 教育经历, ..., leaf:eg_m_staff_education&staff_name, ...  ← 分隔行
行9: 模块首行: 员工教育经历 eg_m_staff_education
行10: edu_uuid, 教育经历UUID, ...
行11: staff_uuid, 员工UUID, ...  ← 外键，关联主表
...
```

## 脚本调用规范

### 调用前必须完成

在调用 `generate_module_excel.py` **之前**，必须完成以下所有工作：

1. ✅ 表设计（所有表名、主键、字段）
2. ✅ 关联关系设计（sub/rel/rel2）
3. ✅ 主键命名验证（确保一致性）
4. ✅ 用户确认

### 脚本是纯执行工具

`generate_module_excel.py` **不接受任何推理或查询**：
- ❌ 不自动推断字段类型
- ❌ 不自动推断关联关系
- ❌ 不自动查找中间表
- ❌ 不自动生成外键字段

所有数据结构必须在调用前**完整准备好**，脚本只负责：
- ✅ 读取 --table-info JSON
- ✅ 读取 --groups 关系定义
- ✅ 按定义生成 Excel

### 正确的调用方式

```bash
python generate_module_excel.py \
  --groups "人员管理|sub:人员学历管理|rel:性格标签管理|rel2:权限管理" \
  --table-info '{"table_name_cn":"人员管理","table_name_en":"person","fields":[{...}]}' \
  --table-info '{"table_name_cn":"人员学历管理","table_name_en":"person_education","fields":[{...}]}' \
  --table-info '{"table_name_cn":"性格标签管理","table_name_en":"tag","fields":[{...}]}' \
  --table-info '{"table_name_cn":"权限管理","table_name_en":"permission","fields":[{...}]}' \
  --table-info '{"table_name_cn":"人员权限关系表","table_name_en":"person_permission","fields":[{...}]}'
  # ... 所有表信息必须完整提供
```
